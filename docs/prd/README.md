# PRDs

Store durable product requirements documents in this directory.

Naming guidance:

- use a short kebab-case feature name
- prefer one PRD per meaningful feature or refactor
- update or supersede older PRDs instead of scattering planning notes across chats

Typical flow:

1. `grill-feature`
2. `write-prd`
3. `prd-to-beads`
4. `ship-bead`
